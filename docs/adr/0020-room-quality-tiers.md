# ADR 0020：房间渲染的精确与实时档位

> 状态：已接受；当前实时策略为 v2，新增浮点候选验收契约与准备优化。日期：2026-10-18。
> 范围：`room-binaural` 的离线渲染、文件流式渲染和 Scene 流式渲染。

## 背景

ADR 0019 消除了无关声源事件导致的反射重复重建。32 源持续运动时，逐源几何、HRIR 查询、
反射合成和动态目标卷积仍消耗较多时间。只放宽 FFT 算术的前置实验改善约 6–13%，
不足以让所有实测主机通过 48 kHz／512 帧的实时预算。

保留现有数值基线作为精确档位，同时提供显式的实时策略，让应用可以选择计算预算和
连续运动反射更新密度。第一版不删除镜像路径，不缩短 FIR，不改变材质、晚场或空间语义。

## 决策

### 会话固定的两种策略

| 策略 | 默认 | FFT | 连续几何斜坡中的早反射／晚场发送更新 |
|---|---|---|---|
| `exact` / `room-exact-v1` | 是 | ADR 0015 标量 | ADR 0019 原有逐源更新点 |
| `realtime` / `room-realtime-v2` | 否 | 原生 AVX／SSE／NEON，能力不足时回退标量 | 1024 帧周期，按声源 ID 错开相位 |

48 kHz 下 1024 帧为约 21.33 ms。直达路径保留原有更新点；headLocked 干声路径也保留原有
更新点。声源几何引起的早反射／晚场发送重建仅在连续斜坡中可推迟；头姿另按 v2 预算处理。
目标滤波器沿用 10 ms 有限淡化。

原生 96 kHz 扩展保持相同物理时长：反射／头姿周期为 2048 帧，源 ID 相位为
0／512／1024／1536 帧，滤波器淡化为 960 帧。内部调度仍为 256 帧。
采样率在会话中固定，两档及各采样率可以同时存在；旧 48 kHz 数值路径保持不变。
v1 的所有头姿变化都立即刷新反射；v2 对纯头姿更新使用下述有限预算。
没有引入共用的世界坐标早反射声场。

档位只在准备资源／创建会话时选择，房间切换不能改变档位。旧 API 与缺省选项继续使用
精确档位。档位固定在实例中，没有进程级环境变量开关，也没有按实时负载静默降级。

### 确定的反射时钟与事件旁路

用固定 SplitMix64 散列将声源 ID 映射到 0／256／512／768 帧相位；每个源每 1024 帧更新。
时钟使用绝对样本位置，不取决于外部块大小、线程完成顺序、其它声源集合或 generation。
采样仍发生在 256 帧内部块边界，调度位图在配置时分配。

以下情况立即刷新，不等待周期：初始状态、声源配置、实时覆盖变化、零时长几何事件、
字段清除、channelLock／screenRef／headLocked 等离散语义变化，以及几何斜坡全部结束后的下一个原有更新点。
精确档位的头姿更新不变；实时档位按下面的预算处理早反射头姿。
离散比较使用原始控制字段有效位，避免屏幕映射补出的有效位置掩盖字段清除。
若反射已过期，下一次完整刷新即使直达形状相同也必须重建反射。

### v2：仅对姿态更新使用有限预算

早反射目标的头姿可以保持，条件为相对最新输入的三维旋转差不超过 **0.5°**，且未到该源的
**1024 帧**绝对网格点（48 kHz 下最多约 21.33 ms）。以相对旋转矩阵的 trace 比较角度，
不直接减 Euler 角，因此能处理 ±180° 接缝、极点和组合旋转。
这两个上限针对保持的目标姿态，不包括原有 10 ms 滤波器淡化，也不是设备端到端延迟。

直达声、headLocked 干声和晚场头姿解码保持原更新点。超过角度预算立即重建反射；
原有硬事件也绕过预算。若新头姿同时需要更新声源几何或补齐之前滞后的几何，
保留 v1 在该样本的完整刷新，避免借头姿节流进一步降低运动声源的几何更新率。

反射目标单独保存姿态，与直达目标分开。强制刷新点由绝对样本和源 ID 决定；
不采用“距上次刷新多少时间”的漂移时钟。每个周期重新锚定状态，保持有限 seek 预热和
同机碎片分块逐位一致。历史和换房预热使用几何／姿态两个周期的较大值；当前两者均为 1024，
因此 v2 没有增加 v1 的预热长度、FIFO 或尾声。

更激进地同时推迟几何刷新会增加密集运动回放误差，未采用。参数对照见
[头姿预算验证](../architecture/ROOM_POSE_BUDGET.md)。

### 缓存、历史与算术隔离

直达和早反射缓存分别保存形状。频谱缓存、准备资源、卷积与输入历史携带档位／FFT 策略；
不同档位不共享这些频谱。原始 HRIR 数据可以共享。两档可在同一进程同时使用。
RustFFT 默认入口仍强制标量；原生规划器只由显式的实时 FFT 调用，见 ADR 0015 的补充。

实时档位的有限 seek 预热及新房间目标预热增加一个反射周期，补足可能滞后的滤波器历史。
换房总预热也计入该周期，保证短响应房间在反射网格重新采样及初始目标淡化完成后才进入混合。
FIFO、FIR 尾声长度、EOS 和显式窗口长度保持原契约；换房仍让旧房间自然排尾。
处理阶段零分配。原有 16 个动态目标容量上限和明确报错继续保留。

### 数值与验收契约

房间 realtime 内核的候选优化允许显式 FMA、固定索引归约重排、SIMD 和 FFT 实现优化，
保持原有 f32／f64 精度层次。exact 保留原表达式与标量 FFT 入口，不使用全局 fast-math、
FTZ 或编译器融合选项。公开 C ABI、档位枚举和选档接口不变。
本轮 v3 融合查询／卷积候选虽然通过数值检查，但 Windows 完整会话短测失败，
因此撤回，当前策略继续为 `room-realtime-v2`。

声学模型、全部距离层、完整 FIR 支持、事件位置、v2 元数据更新网格、淡化、FIFO、延迟
和尾声不变。与同机 v2 的完整输出比较（包含尾声），相对 L2 ≤ `2e-5`，
最大绝对误差／参考峰值 ≤ `2e-4`；静音保持静音，全部输出有限。
不做时间对齐搜索、增益拟合或裁剪。输出帧数、延迟、尾长和资源／事件配置必须相同。
不同版本 realtime 的 PCM 哈希只用于追溯，由上述数值门槛验收；exact 门槛不放宽。

原始 HRIR 时延准备使用独立、全进程最多四线程的有界池，每行 f64 求值顺序不变；
小型输入串行。集合弱缓存命中仍逐层认证长度和 SHA-256，键隔离索引内容、采样率、
展示名称及来源报告。读取、认证和重计算在缓存锁外完成，不建立磁盘缓存。
采用范围、加载收益及验证记录见 [准备优化](../architecture/ROOM_PREPARATION_OPTIMIZATION.md)。
开发与常规正确性检查默认在本地完成；性能筛选优先做 Windows 短测，计时前补齐必要原生烟测。
Windows 短测失败不进入 macOS 性能矩阵或长测。
加载收益不代替运行时验收。

- 精确档位继续使用既有冻结回放与静态 BRIR 门槛，不重新定义精确基线。
  历史 Linux 证据保留，当前主机验收矩阵为 macOS arm64 和 Windows x64。
- 实时档位固定资源、二进制、CPU 能力、事件样本位置及初始状态时，固定／碎片分块输出
  逐位一致；不同 CPU 架构或 FFT 后端不承诺 PCM 位相等。
- 静态 BRIR 与精确档位做数值误差比较；连续运动输出包含有意降低的反射控制更新率，
  单独记录波形误差，不能拿静态 2e-4 门槛替代运动场景的声学／听感判断。
- Release 分别测静态、头姿、换房和 32 源密集斜坡，报告均值、尾延迟与超时次数。
  “实时档位”是处理策略名称，不保证任意硬件、声源数或元数据密度都满足截止时间。

接口与验证记录见 [房间渲染](../architecture/REALTIME_ROOM_RENDERING.md) 和
[第一版档位验证](../architecture/ROOM_QUALITY_V1.md)。
