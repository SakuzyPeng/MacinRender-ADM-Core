# ADR 0018：Scene 流式渲染的数值与重放规则

> 状态：提议，待维护者接受。日期：2026-10-10。
> 对应 [PCM 一致性审计](../architecture/PCM_CONSISTENCY_AUDIT.md)一期 1.1，接续 ADR 0014 至 0017。

## 问题与依据

一期的目标是 Scene 流式渲染的数值计算集中在 Rust，锁定的矩阵在三平台上逐位相同。现有规则只覆盖其中一部分：

- ADR 0014 统一了 Scene 的乘加舍入，但没有替换数学函数；
- ADR 0016、0017 只在重采样和 spreader 内部改用可移植函数。

Scene 实际调用的空间数学、VBAP 与 HRTF 几何、FFT 系数表、HpTF 设计和峰值保护，仍使用 std 的固有方法，
最终调用的是平台数学库（审计 N04、N05、N09–N11、N16、N17）。
C++ 还在做策略改写、VBAP 系数组装、Triple Balance 床系数和输出音量。

1.2 到 1.5 会逐个迁移这些实现。如果没有共同规则，每个切片会各自选择数学库、精度和时序约定。
"逐位相同"也只有在事件位置、时钟、分块和 reset 都固定时才有明确含义。

## 决策

### 1. 精度

- 保持现有精度层次，迁移时不顺带改变：
  - 对象状态、渲染增益、系数和 PCM 为 f32；
  - `scene_math` 中，`cartesian_to_polar`、`direction` 等以 f64 计算三角函数再转回 f32，
    非双耳的 `polar` 则直接用 f32 计算，两者都保持现状；
  - HpTF 的频段参数和滤波状态为 f64，双二阶系数为 f32。
- 实际类型以 1.1 诊断检查点记录的位模式为准。
- 改变任何一处精度都属于数值规则变更，须单独记录，并同步更新门禁。

### 2. 基本算术

- `scene-separate-v1` 扩展到整条 Scene 链路：从策略改写到应用侧输出，乘法和加法分别舍入，不使用融合乘加。
- Rust 实现不调用 `mul_add`，诊断用的历史对照除外。
- C++ 中尚未迁走的运算不再新增 `a*b+c` 形式的表达式。
- 归约按元素、行或声道索引的固定顺序进行，不随线程数、分组或到达顺序变化。
- C++ 运算迁入 Rust 时保留原求值顺序。原表达式可能被编译器融合时，按 ADR 0014 以非融合结果为准，
  不要求复现各平台原有的不同位模式。

### 3. 数学函数

- Scene 链路上的超越函数（`sin`、`cos`、`tan`、`asin`、`atan2`、`hypot`、`exp`、`pow`、`log10` 等）
  一律调用锁定的 `libm` crate（0.2.16），按现有精度选用 f64 或 f32 版本，不再使用 std 的固有方法。
  - 选择 `libm` 而不是扩展 `mradm-math`，理由与 ADR 0017 相同：它是纯 Rust 的 musl 移植，覆盖全部所需函数。
  - 它的 `arch` 特性只把 `sqrt`、`fma`、`rint` 换成硬件指令，这些运算本身就是精确舍入的。
- `mradm-math` 继续服务 rubato 的窗函数和 sinc 表。同一个调用点不在两个库之间切换。
- `sqrt`、四则运算、取整、比较和类型转换都按 IEEE 精确舍入，继续使用 std。
- dB 与线性的换算按精度各设一个 Rust 入口（f32 用 `libm::powf`，f64 用 `libm::pow`）。
  同一个 dB 数值经不同精度入口得到的结果，仍要分别比较。
- Scene 卷积所用的 FFT 系数表（审计 N09）也在本规则范围内。

### 4. 事件、时钟与分块

- **元数据更新**的位置以媒体样本定义：`offset_samples` 是相对于 worker 切片起点的偏移。
- **其他控制**（策略、头部姿态、后端切换、HpTF、音量）在下一个 worker 切片开始时生效。
  重放时这些控制在固定的媒体样本位置注入，就是 `mr_adm_phase2_scene` 的 controls 表。
- **头追踪有效期**为 750 ms，由注入的单调时钟判定。它会改变 worker 切片大小（512 或 1024 帧），
  因此精确比较只使用注入的虚拟时钟，用真实时钟运行不在逐位承诺之内。
- **分块**：输入分块和 worker 切片大小都属于比较配置。只有显式测试过的内核才能声称结果与分块无关；
  其余路径分别比较固定分块和碎片分块。

### 5. reset、epoch 与 EOS

- **epoch 开始时清空的状态**：
  - `begin_epoch` 清空输入队列、generation、策略状态、重采样器、过渡、输出环和帧计数；
  - HpTF 在 epoch 开始时调用 `reset_state`。

  此后的输出只取决于该 epoch 内的输入和控制。
- **帧数换算**：
  - 输出帧数按有理数累加：`input * output_rate / input_rate`，向下取整，余数留到下一次；
  - preroll 跳过的帧数向上取整。
- **EOS**：只有生产已经完成、输出环为空时才报告 EOS。
- **欠载**：欠载时补的零不是数值输出。精确比较只使用无欠载的回放，并比较有效帧数和 EOS。

### 6. 检查点与验收

诊断构建（`MR_ADM_CONSISTENCY_DIAGNOSTICS`）在以下边界记录位模式：

| 边界 | 文件 | 内容 |
|---|---|---|
| 输入 | `scene/*.10-input.f32` | 各元素的 PCM |
| 策略前 | `scene/*.15-producer.f32` 与 `-fields.i32` | 生产者提交的完整状态 |
| 策略后 | `scene/*.21-effective.f32` 与 `-fields.i32` | 生效的完整状态；`.20-effective.f32` 保留原有的部分字段 |
| C++ 交给 Rust 的命令和系数 | `scene/*.30-vbap<N>-*`、`scene/*.30-binaural-*`、`scene/*.30-triple-*`、`triple/g*.30-lane-*` | 渲染器命令和系数 |
| 后端切换前 | `scene/*.35-outgoing.f32`、`.36-incoming.f32` | 混合前的两路输出 |
| 渲染后 | `scene/*.40-render.f32`、`.50-resampled.f32`、`.60-transition.f32` | 渲染、重采样和过渡后的输出 |
| 设备侧 | `hptf/r*.10-coefficients.f32`、`device/e*.70/80/90-*.f32` | HpTF 系数，以及 HpTF 前后和最终输出 |

`run-rust-phase2.py` 要求每个 Scene 用例都产出与其后端对应的上述文件。
每个迁移切片都按 PCM 一致性审计中"每个迁移切片的验证"一节执行：
- 结构迁移提交要求在同一平台上，检查点和 PCM 与切片开始前逐位相同；
- 落实本规则的提交由三平台门禁验收，相对旧输出的变化逐项记录。

## 影响

- 1.2 至 1.5 都按本规则实施。替换数学函数会改变现有 Scene PCM 的最低位，各平台改变的位置不同，
  需要在对应切片中记录，并更新精确门禁。
- 公开 C ABI、Scene 时序契约和生产默认时钟不变。诊断检查点只在诊断构建中编译。
- Rust 内部的 HRTF 插值权重、卷积频谱和峰值保护增益包络，目前仍由内核 scope 和最终 PCM 间接覆盖。
  迁移到对应内核时，在同一切片内补上直接检查点。
