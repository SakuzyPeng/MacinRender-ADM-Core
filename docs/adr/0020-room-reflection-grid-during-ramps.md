# ADR 0020：几何斜坡期间早反射按固定网格更新

> 状态：提议，待维护者评估。日期：2026-10-13。
> 范围：`room-binaural` 的 Rust 会话（`mradm-dsp` `room::session` / `signal` / `prepared`）。离线渲染、
> 文件流式渲染和 Scene 流式渲染共用该会话，结论同时适用于三者。
> 前提：[ADR 0019](0019-room-per-source-update-grid.md)（按声源自身的事件网格更新）。

## 问题与依据

ADR 0019 之后，处于位置斜坡中的声源仍在自己的每个更新点完整重建：直达路径、约 20 条早反射路径
（每条一次 HRIR 查询，加上分数延时、材料滤波和目标 FFT），以及晚场发送。斜坡期间至少每个块起点
（256 帧，187.5 Hz）重建一次。

维护者在三个平台用 `room_bench` 的斜坡场景复测：32 个声源，每次 512 帧调用有 32 个不同事件偏移，
连续头姿，共 2,814 次调用。超过 10.667 ms 预算的调用为 macOS 16 次、Windows 2,804 次、Linux 2,814 次。

在 Linux x64 云主机上对 32 个声源、每次调用 512 帧做分阶段计时（单线程，合成资源包，尺寸与参考预设相近）：

| 每次调用 | 重建次数 | HRIR 查询 | 响应合成（含 HRIR 查询） | 目标滤波器 | 卷积 | 晚场 |
| --- | ---: | --- | ---: | ---: | ---: | ---: |
| 连续头姿 | 32 | 678 次 | 13.1 ms | 3.3 ms | 4.1 ms | 4.4 ms |
| 全部斜坡 | 96 | 1,973 次 | 60.0 ms | 12.8 ms | 9.9 ms | 5.0 ms |

斜坡场景约 80% 的时间用于重建，主要是早反射。早反射的目标更换本来就经过 10 ms 的有限窗口交叉淡化，
按 187.5 Hz 重新计算完整的早反射超出了必要的更新率。

## 决策（提议）

### 1. 斜坡期间早反射只在固定网格上更新

在一个声源的更新点（ADR 0019），若同时满足：

- 该声源有几何字段（`GEOMETRY_FIELDS`）正在插值；
- 头姿与上次更新相同；
- 该点的绝对样本位置不是网格长度 G 的整数倍；

则只更新直达分支，早反射与晚场发送标记为待更新。其余情况与 ADR 0019 相同，更新全部分支。

G 为 256 的整数倍，所以网格点总是块起点，也总是每个声源的更新点。由此：

- 斜坡期间早反射和晚场发送最多滞后 G 帧（G = 1024 时为 21.3 ms）；
- 斜坡结束后的第一个更新点（最多 256 帧之后）不再处于斜坡中，所有分支随即更新；
- 头姿变化、几何跳变（时长为 0）、screenRef 与 headLocked 切换、首次构建都立即更新所有分支；
- 增益等非几何字段的斜坡不触发延后。

### 2. 分开直达与早反射的路径缓存

点声源的路径与传递函数缓存按分支分开记录。只更新直达分支时不计算早反射路径，留到下一次完整更新。
两个分支同时更新时，计算内容与原实现相同，输出逐位相同。

### 3. 数值规则不变

归约顺序、FFT、舍入、目标滤波器淡化（10 ms 有限窗口）和 16 个目标的上限都不变。网格位于绝对样本位置，
固定分块与碎片分块逐位一致；处理阶段不分配内存。

### 4. 网格长度

提议 G = 1024（约 47 Hz），同时评估 512。评估结束后固定为常量，不作为用户参数。

## 评估开关（临时）

为在维护者机器上实测，本提议先以默认关闭的诊断开关实现：

- 环境变量 `MR_ADM_ROOM_REFLECTION_GRID` 在会话准备时读取，处理阶段不读取。未设置或为 0 时关闭，
  输出与 ADR 0019 逐位相同；取值必须为 0 或不超过 65536 的 256 的整数倍，否则会话创建失败。
- 开关作用于进程内所有房间会话，包括 C ABI 与 `mradm render`，因此也可用于听音对比。
- `Session::set_reflection_grid` 仅供测试；`room_bench` 每行输出 `reflection_grid`。
- 开关只用于评估，不得用于发行构建或作为验收依据。本 ADR 接受或否决后删除开关。

## 本机测量

基线为 `7d92315`，机器、预设和 HRIR 与 ADR 0019 的验证相同（Linux x64 云主机 4 vCPU，
`reference-7x6x3.2-corrected-v1`，公开的 SADIE II D2）。

- **开关关闭。** 11 个会话场景和 `room_replay` 同一调度（有无屏幕，固定与碎片分块）与 ADR 0019
  构建逐位相同。
- **G = 1024 的输出差异**（相对开关关闭，跳过前 100 ms）：

  | 场景 | 相对 L2 | 最大样本差 / 峰值 |
  | --- | ---: | ---: |
  | 32 个声源全部斜坡，16 个偏移，连续头姿 | -61.8 dB | 0.21% |
  | 32 个声源全部斜坡，16 个偏移，无头动 | -54.6 dB | 0.56% |
  | 8 个声源斜坡，4 个偏移，连续头姿，含 LFE | -59.4 dB | 0.35% |
  | 1 个声源快速运动（约 62°/s），无头动 | -41.3 dB | 2.7% |
  | `room_replay` 调度（第 1033–53475 帧改变） | -48.2 dB | 3.5% |

  G = 512 时单声源快速运动为 -47.7 dB / 1.1%。连续头姿时每次调用开头都因头姿完整更新，512 与 1024 相同。
- **耗时。** 以下测量进行中，结果补入[实时房间验证](../architecture/REALTIME_ROOM_VALIDATION.md)。

## 考虑过的其他方案

- **所有分支统一降低更新率。** 直达路径的延时步长变大，交叉淡化期间的梳状滤波更明显。不采用。
- **头姿变化也按网格延后早反射。** 头动时早反射滞后于直达声，感知风险更大。不在本决策内。
- **逐位不变的加速**（HRIR 查询、路径合成）。受 ADR 0014 / 0015 约束，预计只能节省 20–30%，
  不足以让 Windows / Linux 满足预算。可另行推进，与本决策不冲突。
- **按运动幅度阈值跳过更新。** 结果依赖数据，阈值难以论证。不采用。

## 影响

- **输出变化范围。** 只在几何斜坡期间改变，晚场随后把差异带入尾声。静态声源、只有头动、跳变、
  只有增益斜坡的会话不变。
- **冻结回放。** `room_replay` 中声源 1 的位置斜坡（样本 731–2268）会改变输出，冻结回放和带屏幕回放的
  哈希都会变化，接受后需在三平台重新确立基线。28 个参考点的 BRIR 都是静态声源，不受影响。
- **公开接口。** C ABI、Scene 时序契约和事件位置定义（ADR 0018 §4）不变。

## 评估与验收

1. 维护者在三平台打开开关（512 与 1024）运行 `room_bench`（含 `source_ramps` 场景）和 Scene 流式长测，
   比较超时次数。
2. 听音对比：打开与关闭开关，用 `mradm render --renderer room-binaural` 渲染含快速运动对象的节目做盲听；
   同时记录客观差异。
3. 根据结果选定 G 或否决本提议。
4. 接受后：删除开关并固定 G；三平台重新确立 `room_replay` 冻结哈希；把开关相关测试改为常态回归；
   更新验证文档。
