# 房间实时档位 v2：早反射头姿预算

日期：2026-10-13。基线为 `e5803f6` 加上已验证的直达轻量路径；比较对象是原实时档位的
头姿处理，不是精确档位。完整参数矩阵、误差、源码／二进制哈希和验证记录见
[JSON](ROOM_POSE_BUDGET.json)。

## 保留的策略

`realtime` 使用 `room-realtime-v2`：早反射目标允许最多 **0.5°** 的三维旋转偏差，
在每源的 **1024 帧绝对网格**上强制追上输入姿态（48 kHz 下约 21.33 ms）。
直达声、headLocked 干声和晚场头姿解码保留原更新点。超出角度预算、硬事件或需要
补齐声源几何时立即刷新；不借此进一步降低运动声源的几何更新率。

角度由相对旋转矩阵计算，处理 ±180° 接缝和组合旋转；时钟使用绝对样本和源 ID，
不依赖外部分块、墙钟负载或“距上次更新多久”。0.5°／1024 帧约束的是保持的反射目标，
不包含原有 10 ms 目标淡化、传播／保护时延或设备队列。

精确档位仍是 `room-exact-v1`。CLI／C++／C API 的选档方式不变，检查 JSON 增加
`reflection_pose_limit_degrees` 和 `reflection_pose_update_frames`，并报告新的处理策略名。
公开 C ABI 仍为 v1.48，既有函数和 POD 布局不变。

## 为什么加几何保护

初始测试了三组不保留几何追赶的预算：0.5°／512 帧、0.5°／1024 帧、1°／1024 帧。
21 ms 配置在密集运动中更快，但小头动被延后后，v1 原本随头姿发生的几何追赶也变少了。

以 Mac 为例，相对 v1 实时输出：

| 参数 | 缓慢头动 | 密集运动＋缓慢头动 | 密集运动＋接缝／近极点 |
|---|---:|---:|---:|
| 0.5°／512 帧 | 0.0249% | 0.3831% | 0.5565% |
| 0.5°／1024 帧，未保留几何追赶 | 0.5173% | 1.7323% | 2.6098% |
| 1°／1024 帧，未保留几何追赶 | 0.5192% | 1.9020% | 2.6098% |
| **保留：0.5°／1024 帧，保持几何追赶** | **0.0539%** | **0.0068%** | **0.0056%** |

表中为整份 PCM（含尾声）的相对 L2。保留版本在新头姿与几何过期同时出现时仍完整刷新，
仅在几何已跟上时保持反射姿态。其密集运动性能收益因此很小，这是为控制误差作出的选择。
其它更激进配置仅保留实验记录，没有作为产品默认。

## Release 性能

三平台均为 Rust 1.98.0 Release，关闭 profile／trace。固定相同房间、HRIR 和事件时间，
32 源、48 kHz／512 帧，每进程预热 32 次后测 938 次；基线与保留版交替三轮，第二轮反向。
worker 固定为 Mac 8、Windows 8、Linux 32。原型筛选与最终保留版使用独立的对照轮次。
以下均值和 p99 为三轮各自统计值的中位数，超时累计 2814 次调用。

纯头追场景：声源位置静止，头姿以 93.75 Hz 更新，每次 yaw／pitch／roll 增加
0.25°／0.05°／0.02°。

| 主机 | v1 均值 ms | v2 均值 ms | 耗时下降 | p99：v1 → v2 ms | 超时：v1 → v2 |
|---|---:|---:|---:|---:|---:|
| Mac M4 Pro | 1.666 | 1.321 | 20.7% | 1.975 → 1.691 | 0 → 0 |
| Windows i7-11800H | 3.418 | 2.722 | 20.3% | 4.619 → 4.066 | 0 → 0 |
| Linux 共享云主机 | 7.711 | 7.670 | 0.5% | 25.272 → 23.883 | 545 → 498 |

其它场景平均耗时：

| 主机 | 静态 v1 → v2 ms | 头追＋换房 v1 → v2 ms | 32 源持续运动 v1 → v2 ms |
|---|---:|---:|---:|
| Mac | 0.543 → 0.543 | 1.845 → 1.459 | 2.761 → 2.709 |
| Windows | 0.789 → 0.778 | 4.088 → 3.344 | 6.469 → 6.488 |
| Linux | 4.547 → 4.853 | 8.337 → 8.546 | 11.719 → 12.061 |

桌面机的收益集中在头追与头追换房；全源持续运动基本没有改善。不能据此宣称所有房间负载
都快 20%。计时仅含 `Session::process`，不含解码、设备和准备；探针不按墙钟节拍送音频。

Linux 波动较大。另做两组独立的纯头追对照，每组每配置 3000 次调用、次序为基线／候选、
候选／基线：基线 7.721／11.906 ms，候选 6.861／6.787 ms。两组都更快，但幅度从约 11%
到 43%，因此不据此给出稳定的 Linux 加速比例，零超时也仍未通过。

## 正确性与边界

- 三平台保留版本各通过 **89 项 Rust 测试**：58 库、21 房间、9 档位、1 零分配。
  覆盖实际旋转差、直达与参考逐位一致、大角度／截止点旁路、几何追赶与参考逐位一致、
  各源相位的有限预热、非块边界小头动、碎片输入、换房、EOS 和同声学短房间切换。
- 所有参数候选和保留版都通过 Release 固定／碎片分块回放。精确档位冻结 PCM 不变，
  HRIR 和静态 BRIR 检查点不变。标准回放中较大的头姿步进，以及快速转头密集回放，
  保留版与 v1 实时 PCM 逐位一致。
- 保留版额外波形误差在所测三组慢头动回放中最大约 **0.054%**；这是相对 v1 实时档位，
  不能与 v1 相对精确档位的运动误差简单相加。尚未进行主观 A/B 试听，不声称听感无差别。
- macOS Debug CTest **80/80**，Release 房间集成 **1/1**；Windows canonical MSVC 构建和
  房间／C header CTest **2/2**。clippy（dsp／ffi 全 targets、sofa＋room-trace）、
  C/C++ 质量门禁和 FFI 头校验均通过。
- Release CLI 已确认策略名与预算正确。参考包精确／实时预热仍为 69119／70143 帧，
  FIFO 仍为 256 帧，尾声仍为 67352 帧；未增加处理 FIFO。
- Windows／Linux 原源码均已恢复，Windows 原 Git 状态也恢复；沿用现有构建缓存。

`room_replay` 增加 `--head-motion standard|slow|fast|wrap`，原调用保持原默认轨迹。
完整日志与原型源码保存在忽略的 `local/room-v1/pose-budget-20261013/`。
