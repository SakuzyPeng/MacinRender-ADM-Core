## 实现与正确性边界

每条 EQ 的前 2048 taps 仍在 CPU。后续保留原 2048 帧分区、4096 点变换和完整支持长度；
每个房间最多批量处理 64 条独立直达／湿声 EQ 链。GPU 按固定分区顺序归约，维持 f32 运算。
CPU 只保留长分区的前一段时域输入和新窗口，释放原完整频谱历史环；GPU 持有频谱历史。
准备数据中的 FIR 频谱保持原样，不影响 exact 或其他未选择实验的路径。

一块收齐后生成未来 EQ 输出，在下一 canonical block 使用前完成等待和安装，沿用原有
消费位置，没有增加 FIFO、改变延迟或缩短尾声。处理中不创建 FFT 计划或扩大缓冲。
重置先于历史复制，历史复制先于当前行写入；直达／湿声配对在同一个 GPU 线程中处理各 bin，
避免复制到更新后的源历史。CPU 记录 generation，reset 后取回的旧结果被丢弃。

私有 DLL 增加 EQ 批次接口。完整缺少该组接口的旧 DLL 仍走 CPU EQ，以便使用同一 Rust
可执行文件作配对对照；部分缺失接口会报错。公共 C ABI、默认 realtime 与 exact 入口不变。

本地 macOS arm64 检查通过：GPU 参考执行器的 48／96 kHz 长 EQ、不同 EQ 长度和系数、
直达到湿声历史复制、待取回时 reset、声源停启、换房各阶段和完整尾声；包含处理阶段零分配。
原质量、零分配测试分别在开启／关闭 GPU 特性时通过，clippy warnings denied 通过。

Windows 原生 [EQ 状态回归工具](../../scripts/research/room_gpu/eq_batch_test.py) 用独立稀疏 FIR
时域参考检查 9 个用例，覆盖 64／16／2 条链、部分更新、重置后复制、静音、错误重复提交及
错误完成尺寸。最大相对 L2 为 `4.224901618e-7`，最大误差／参考峰值为 `1.146200117e-6`。
它是状态和变换回归，不是性能证据或完整声学验收。MSVC 原生构建、C++ 格式和 cppcheck 通过。

## 重复换房长测记录

同一套冻结二进制及内核源码，22,500 次调用、120 秒音频，每 512 次调用请求换房，实际共 44 次：

| 均值 ms | p99 ms | 最大 ms | 超时 |
|---:|---:|---:|---:|
| 2.798931 | 10.4053 | **29.4060** | **457/22500** |

本轮先测重复换房以检验正在修复的问题；按当时门槛停止了固定六轮运动长测及 macOS 性能矩阵。
没有关闭日常应用或调整驱动／功耗，没有并行构建或其他本任务基准。运行前后为 AC，背景 CPU
快照约 3.03%–8.08%；所有超时照常计入。峰值工作集为 2,196,541,440 bytes，包含准备阶段。
44 次新实例准备累计约 90.025 秒，位于 DSP 计时窗口外，不能抵消任何超时。

保留的最慢 32 次中，按原事件时序推算，4 次在预热、7 次在淡化、20 次在排尾、1 次在稳态；
其中 28 次的调用序号模 4 为 0。最大值在含预热调用 `9220`，已在该次过渡结束后的稳态。
EQ 未来结果通常在前一调用提交、下一调用取回，因此这些记录提示应检查 GPU 等待和资源使用。
**没有在失败长测中记录阶段计时，不能将上述推测当作具体等待原因的证明**；也不能把最慢 32 次
的分布推广到全部 457 次超时。
没有以同样重复换房强度对旧 DLL 做长测，因此不能用不同工作负载的历史结果断言所有劣化都由
EQ 迁移引起。超时记录仍然成立，不以背景负载作废，也不继续占用排查。
