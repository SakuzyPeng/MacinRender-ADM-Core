## 实现边界

稳定房间、没有 headLocked 信号／历史尾声、没有待切换房间、未开始 EOS 时，可使用流水路径。
每块先将 256 帧音频、状态、方向和更新标记复制到 worker 独立拥有的缓冲，然后在八个 worker
渲染当前块时，由原调用线程准备下一块输入。完成当前块后补齐原 FIFO 对应的输出，再推进下一块。
本轮派发的房间 worker 主任务在 `process()` 返回前完成，直达／早反射 GPU 批次仍按原 256 帧顺序运行。
原有晚场大分区异步任务继续沿用既定的下一块消费时序，没有新增排队延迟。

换房、headLocked 和 EOS 继续使用原串行路径；本轮没有扩大这些场景的并行范围。
输入准备错误或 panic 都先收齐 worker 工作，再返回／传播，避免遗留 mailbox 结果或污染后续会话。
工作线程数量仍为八，输入准备使用原调用线程，不增加准备线程池。

只有位置插值尚未结束、其他字段与 live override 已稳定的输入段，才复用合并后的静态控制字段。
每个样本的位置仍用原绝对样本位置的 f64 表达式计算；保留逐样本屏幕映射、方向追踪、原点回退、
有效性切换以及增益／diffuse／headLocked 音频处理顺序。其他控制组合沿用原求值路径。

## 本地正确性

- 48／96 kHz 的 CPU 参考执行器对照通过：运动、屏幕映射、跨原点、位置字段 clear、碎片分包和尾声。
- GPU 参考执行器的 512 帧与碎片分包输出逐位一致，处理线程零分配。
- 原换房／headLocked／reset／尾声用例、质量 9 项、原零分配检查通过。
- 控制投影逐位对照通过；worker rendezvous 验证实际发生重叠，并验证准备错误与 panic 后可再次派发。
- clippy（warnings denied）及 GPU＋HOA 特性共编译检查通过。GPU 与 HOA 不因此获得混合使用支持。

## Windows 短测

canonical MSVC／Rust、独立无插桩 Release，使用原缓存和相同原生 96 kHz 九层集合。
固定八个 worker、512 帧、32 源、realtime；正常桌面环境，负载不作为排除超时的理由。
每项先预热 32 次，再测 1024 次。

| 场景 | 均值 ms | p99 ms | 最大 ms | 超时 |
|---|---:|---:|---:|---:|
| 位置运动 | 2.895372 | 3.5567 | 3.7927 | 0 |
| 距离运动 | 2.828427 | 3.4275 | 4.0902 | 0 |

本轮没有与旧候选交替配对，因此不将历史轮次差异作为严格加速百分比。
`room_bench` 现保留最慢 32 次调用的序号；只复用已有计时值，在处理结束后生成索引和 JSON，
没有给处理循环新增时钟或输出操作。CPU 总量取样在该后处理之前完成。

## Windows 长测

首轮位置运动：22,500 次调用，平均 **2.930026 ms**、p99 **3.6558 ms**、最大 **5.4662 ms**，
**1 次超过 5.333333… ms**。超时调用的零基测量序号为 `21546`，含预热的基准调用序号为 `21578`。
第二慢为 4.4795 ms；这一分布不能解释唯一尖峰的原因，也不改变失败结论。
其余五轮已停止；没有排除任何超时或继续占用排查。

测试前后均接通电源，背景 CPU 快照约 2.11%–8.27%；快照不能代表超时发生时的负载。
观察到的进程峰值工作集为 1,707,589,632 bytes，包含准备阶段。没有独立测量进程显存峰值。

## Windows 数值

默认回放始终有 headLocked 源，主要验证串行回退；因此新增显式 `--world-only` 回放，
用相同 32 源、屏幕／头姿／密集位置事件、换房、源移除和 EOS 验证流水路径。
它去掉 headLocked 初态及切换事件，写入独立 scenario 和 world_only 标记，避免混同比较。
该测试选项不改变生产渲染选档。

| 回放 | 完整帧数 | 最大相对 L2 | 最大误差／参考峰值 |
|---|---:|---:|---:|
| 默认回放（含 headLocked） | 231581 | 4.898492078e-7 | 6.516114024e-7 |
| 纯世界坐标回放 | 231581 | 5.191120910e-7 | 6.468046673e-7 |

门槛分别为 `2e-5` 和 `2e-4`。两者均保留完整尾声和 256 帧延迟，输出有限；
不搜索时移、不拟合增益、不裁剪。输入为 96013 帧，EOS 后实际输出 135568 帧。
manifest 的 tail_frames=135502 描述初始准备房间；排尾终点取换房后的 Session 实际状态。
纯世界坐标回放在 512 帧与碎片输入下逐位一致。
默认回放先完成，随后仅增补回放程序的测试选项；被计时的基准程序和 GPU DLL 哈希未改变。

## 复现与限制

沿用 [GPU 工具说明](../../scripts/research/room_gpu/README.md#完整-session-研究入口) 的构建及
两个 1024 次短测命令。数值检查分别运行默认回放和追加 `--world-only` 的回放，各比较同机 CPU
与 GPU 的完整文件；其余参数为 `--quality realtime --dense --screens --head-motion wrap`。
只有两项短测和数值门槛均通过，才执行两个场景各三轮、每轮 22500 次的长测，任一超时即停止。

该原型仍限本次 Windows CUDA／96 kHz 资源族和最多 32 源；未验证音频设备欠载或生产 API 接入。
macOS 本轮完成本地正确性验证，没有 macOS GPU 后端；Windows 长测失败后未安排 macOS 性能测试。

运行时恢复到本轮之前保留的 GPU 原型。Windows 覆盖核对 355 项，恢复 87 个原文件、移除 268 个任务文件，
原 HEAD 与 Git 状态一致。本地和 Windows 临时私有资源已清理，原缓存及已有研究改动保留。
