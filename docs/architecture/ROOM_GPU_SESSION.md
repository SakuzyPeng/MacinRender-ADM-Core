## 与组件探针的区别

本轮直接使用现有 `Session` 和 `room_bench` 的事件序列。CPU 在计时范围内处理真实的逐源事件、
几何、三角形查询、距离插值权重和时延分解；不再循环预计算运动快照。

GPU 执行直达／早反射的响应构造、目标 FFT、输入频谱历史和动态卷积。每个源仍按原样本位置
更新目标，保留 10 ms 有限移动平均淡化。最多 16 个活动目标使用 32 个物理槽，避免一个块内
回收的槽覆盖前半块仍需使用的滤波器。每个目标只卷积一次，子范围按原有权重和顺序混合。

原 Session 的 EQ、晚场发送、晚场卷积／解码、LFE、headLocked、语义展开、FIFO、reset 和换房
处理继续运行。八个 CPU worker 完成逐源准备后提交 GPU；CPU 晚场工作与 GPU 重叠，最终等待
GPU 输出，再保持原有逐源和逐分支求和顺序。没有新增音频排队延迟或缩短 FIR。

GPU 后端只提供私有研究 DLL，公共 C ABI、枚举和生产选档没有扩展。该原型还不等于公开 C API、
文件流式渲染／离线渲染入口或音频设备已经提供了 GPU 支持。

## 正确性与检查

同机 CPU 与 GPU 完整回放均为 **231,581 帧**，涵盖原回放的运动、屏幕、headLocked、extent／
diffuse、换房、分包及尾声。GPU 固定和碎片分包输出逐位一致。完整检查点比较结果：

- 最大相对 L2：`4.869347866e-7`，门槛 `2e-5`。
- 最大误差／参考峰值：`6.516114024e-7`，门槛 `2e-4`。
- 帧数、延迟、尾长和资源配置相同；不作时间搜索、增益拟合或裁剪，输出有限。

原 GPU manifest 的研究标记保留。比较时只在另一个派生 manifest 中移除已验证的
`room-gpu-session` 标记，其余配置由原数值比较工具核对。生产比较工具仍拒绝任意声学实验。

本地 CPU 参考执行器先验证了任务收集与有限淡化：48／96 kHz 的真实 Session、碎片输入、运动、
headLocked、extent／diffuse、LFE、换房、reset 和完整尾声通过，Rust 各处理线程零分配检查通过。
原质量测试 9 项、原零分配测试、新 GPU Session 测试、clippy（warnings denied）、cppcheck 和格式
检查通过。CUDA 驱动内部的分配和设备丢失恢复尚未认证。

## 原型边界

- Native 后端限于本次 96 kHz／4096 点响应 FFT 的资源族、最多 32 源；不兼容的形状明确报错。
- 帧内容量有界：256 次目标更新、1024 个非空响应桶、2048 个卷积任务；逐源路径和目标容量也有限。
  不能把这些原型限制视为生产 API 的新承诺。
- GPU HRIR 表仍来自受控的离线测试 fixture。生产准备路径尚未接入，不能把这个目录当永久磁盘缓存。
- GPU 和已有 HOA 声学研究各自独立；同时编译通过不代表两种实验可以混合用于一个换房链路。
- 该候选未提交、未晋级为生产策略。默认构建不链接 CUDA，也不会自动选择 GPU。
