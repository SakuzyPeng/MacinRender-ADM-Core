# ROOM 房间几何自动映射

ROOM 默认以听者为原点，把归一化 XYZ 分别映射到房间各轴的可用长度。
离线渲染、文件流式渲染和 Scene 流式渲染共用 Rust 几何与空间处理实现。
这是房间渲染的坐标解释；不依赖或新增 ADM `absoluteDistance` 消费。

## 坐标与约束

先将 ADM／Scene 坐标转换到房间轴：`u = (y, -x, z)`。对每个房间轴，
听者坐标为 `L`、房间尺寸为 `D`、边界留距为 `c`：

- `u >= 0`：物理偏移为 `u × (D - c - L)`。
- `u < 0`：物理偏移为 `u × (L - c)`。

物理位置为 `L + 偏移`，距离为偏移向量长度。正负 1 到达保留留距后的墙面；
斜向位置按各轴独立映射，因此长方体房间中的最终角度由物理位置决定。
极坐标先转换为 XYZ，再执行相同映射。改变听者位置会重新确定各轴两侧的可用长度。

映射后仍应用最小距离和沿射线的边界约束。参考房间的最小距离保持 0.25 m，
输入零位置保留此前非零位置的方向；没有历史方向时使用前方。有限的越界输入
沿其物理方向限制到房间边界，不逐轴截断，不改变已有 HRTF 端点钳制规则。

参考房间为 `7 × 6 × 3.2 m`，听者为 `[3.4, 3.0, 1.2] m`，留距为 0.15 m：
ADM `(0, 1, 0)` 位于听者前方 3.45 m；`(0, 0.5, 0)` 位于前方 1.725 m。
显式指定 1.5 m/unit 时，这两个位置仍分别是前方 1.5 m 和 0.75 m。

## 接口

- CLI 省略 `--room-metres-per-unit` 时默认自动映射；显式正数使用固定比例。
- C++ 内部 `RoomConfig` 和 C ABI `adm_room_config_t` 的 `metres_per_unit=0` 表示自动。
  正数范围保持 `[0.01, 100]`；其余值和非有限数被拒绝。
- C ABI v1.49 保留公开 POD 布局、函数签名和既有符号。既有传入正数的调用保持原数值路径。
- 准备报告的 `coordinate_mapping` 给出 `room`／`uniform` 模式、比例（自动时为 null）、
  听者位置、房间尺寸、边界留距和最小距离。`room-check` 报告默认自动模式。

## 空间处理与换房

自动模式在各房间分支内分别完成映射，再进行保持物理半径的屏幕映射。
extent／divergence 样点保留映射后的米制半径，再逐射线限制到边界；不会再次按房间缩放。
对象尺寸的既有角度计算、channelLock、直达与早期反射的距离 HRTF 查询策略保持各自语义。
原点处保留上一个非零位置是否应用屏幕映射的状态，避免屏幕切换使原点方向跳变。

会话创建时固定映射模式。自动模式换房时，旧、新房间各自使用自身几何并沿用既有淡化；
head-locked 直达声使用会话初始房间的尺度。位置查询与渲染使用相同映射。
固定比例模式沿用原算术与屏幕处理顺序，不重写已有 PCM 基线。

## 验证

`room_mapping` 覆盖六面、非居中听者、斜向、不同尺寸、边界、原点、非法输入、
物理位置 PCM 对照、屏幕映射、采样时间线和换房。`room_distance` 和 `room_no_alloc`
同时检查固定比例与自动模式，覆盖头锁、extent／divergence、分包、reset 和工作线程分配。
`room_96k_test.py` 通过公开 CLI／C ABI 对比离线渲染、文件流式 seek、Scene 分包及两种质量档位。
性能工具 `room_bench --automatic-mapping` 使用与固定比例模式相同的目标物理轨迹，
并在结果中记录映射模式。性能数据仅使用无插桩 Release。

### 2026-10-19 验证结果

macOS Debug 全量 85 项 CTest 通过；macOS／Windows Release 的 CLI、文件流式 seek、
Scene 分包对照通过。显式 1.5 m/unit 的 Release 对照 PCM 与原工作区版本逐字节一致。
公开 ABI 布局及私有 FFI 检查通过。完整记录见 [validation.json](evidence/room-coordinate-mapping/validation.json)。

Windows CPU 短测使用 8 workers、96 kHz、512 帧、32 源、1024 次位置运动调用。
同一候选二进制的固定比例／自动模式均值为 12.122／12.369 ms，两者各 1024 次超时；
因此未通过 5.333 ms 零超时门槛，停止距离运动、macOS 性能及六轮长测。
这是同一二进制两种模式的对照，不作为修改前后的严格性能基线，也不宣称 CUDA 验收通过。
