# 房间直达路径与 worker 调度试验

日期：2026-10-13。基线为 `e5803f6`，包含实时房间换房预热修复；本轮性能均使用
`realtime` 档位。原始数值摘要、源码／二进制哈希和各阶段结果见
[JSON 记录](ROOM_DIRECT_WORKERS.json)。

## 结论与保留范围

保留直达路径优化：只清理所请求分支上次写入的频谱桶；直达更新仅访问唯一的直达镜像。
未请求的时域输出平面仍清零，保持 `ResponseWork` 的调用契约。路径、FFT、归约顺序、
反射更新时钟、FIR 支持、FIFO 与声学模型均不变，没有引入新的近似。

worker 默认策略暂不修改。Windows 测试机在 32 源密集运动时用 16 线程有额外收益，
但 1／16 源未普遍受益；Mac 扩到 16 线程的筛选优势未在独立复测中保持。
Linux 本轮仍以原有 32 线程较合适。这里的数量只代表所测主机，不能直接推广到所有硬件。

不保留 Rayon 最小任务粒度 4 的实验。它在短筛选／四场景矩阵中出现过优势，
但独立、平衡顺序的复测明显弱于保留的直达优化。此次只试验线程数与任务粒度；
条件变量 mailbox 和跨 256 帧块的调度合并尚未修改。

## 方法

- 同一冻结房间与个人 HRIR，48 kHz／512 帧，每次调用预算 10.667 ms。Rust 1.98.0 Release，
  关闭 profile／trace，复用各主机已有 Cargo target；每台主机先完成构建和正确性检查，再计时。
- `base`：基线实现；`direct`：直达及稀疏清零优化；`grain4`：在 `direct` 上给声源并行迭代
  添加 `with_min_len(4)`，同时覆盖两个房间过渡中的成对声源作业。
- 筛选：4／8／16／32 workers，每配置两轮、每轮 256 次，第二轮反向运行。
  随后对默认配置及筛选选出的配置做三轮独立 938 次调用，覆盖静态、头姿、换房、密集运动。
- 最后独立复测密集运动：每进程预热 32 次，测 938 次；每配置事先另跑 256 次预热。
  Mac／Linux 三个配置跑六种顺序，Windows 四个配置轮换四次，使每配置占据各顺序位置的次数相同。
  32 源各自偏移的位置斜坡与 93.75 Hz 头姿输入完全相同。
- 下表均值合并全部调用；p99 为每轮 p99 的中位数，并非合并样本后的 p99。
  最大值和超时数涵盖全部复测调用。计时仅包含 `Session::process`，不包含解码、准备和设备链路。
  探针不按墙钟节拍喂音频，OS 调度和共享主机负载未受控。

## 直达准备微基准

预先计算 64 个移动位置和旋转，在不同延时桶之间切换，单独测直达响应准备。
每轮 6000 次，基线与候选交替三轮；取各轮均值的中位数。

| 主机 | 基线 μs | 优化后 μs | 耗时下降 |
|---|---:|---:|---:|
| Mac M4 Pro | 12.018 | 11.149 | 7.2% |
| Windows i7-11800H | 20.523 | 17.655 | 14.0% |
| Linux Xeon Platinum 8352V | 76.470 | 65.965 | 13.7% |

这是响应准备一个阶段的收益，不能当作完整渲染的加速比例。

## 平衡顺序复测：32 源密集运动

| 主机／配置 | 均值 ms | p99 ms | 最大 ms | 超时 / 调用 |
|---|---:|---:|---:|---:|
| Mac 基线，8 workers | 2.853 | 3.474 | 17.702 | 4 / 5628 |
| Mac 直达优化，8 workers | 2.823 | 3.270 | 13.956 | 4 / 5628 |
| Mac 直达＋粒度 4，8 workers | 3.194 | 3.768 | 20.257 | 8 / 5628 |
| Windows 基线，8 workers | 7.208 | 9.024 | 10.337 | 0 / 3752 |
| Windows 直达优化，8 workers | 6.683 | 8.490 | 12.745 | 2 / 3752 |
| Windows 直达优化，16 workers | 6.477 | 7.951 | 10.175 | 0 / 3752 |
| Windows 直达＋粒度 4，8 workers | 7.003 | 8.791 | 9.998 | 0 / 3752 |
| Linux 基线，32 workers | 14.708 | 34.524 | 56.483 | 3141 / 5628 |
| Linux 直达优化，32 workers | 12.434 | 31.165 | 47.366 | 2229 / 5628 |
| Linux 直达＋粒度 4，16 workers | 18.683 | 40.289 | 53.074 | 4727 / 5628 |

直达优化的整段均值下降：Mac 约 **1.0%**，Windows 约 **7.3%**，Linux 本轮约 **15.5%**。
Windows 将 worker 数从 8 增至 16，再下降约 **3.1%**，相对原基线合计 **10.1%**。
Mac 的幅度很小，超时次数也没有下降，不能据此宣称已解决尾延迟。

Linux 是共享云主机，基线各轮均值为 12.33–19.08 ms，候选为 11.68–13.14 ms。
虽然本轮各配对轮次候选都更快，但波动足以影响收益幅度；15.5% 不能作为独占环境的稳定承诺。
它的平均耗时和 p99 仍超预算。Windows 本轮基线本身就没有超时，不能把第一版记录中的
超时次数变化全部归因于这次优化。各结论应使用本轮同时运行的基线比较，不能混用不同批次的绝对值。

## 线程数选择

保留原默认：macOS／Windows 上限 8，Linux 按有效并行度、上限 32。
需要复现 Windows 32 源高负载选项时，在进程启动前设置 `MR_ADM_ROOM_WORKERS=16`；
现有诊断覆盖只在准备线程池时读取，会话中不会动态变更。

较小源数各测一轮：Windows 1 源静态均值从 0.262 ms 增至 0.362 ms；
16 源运动从 4.131 ms 变成 4.142 ms。增加线程对这些负载没有明确好处，
本轮不据单台机器的一个负载修改产品通用默认。

## 正确性与复现

- 三平台的 `direct` 和 `grain4` 各通过 28 项定向 Rust 测试：21 项房间、6 项档位、1 项零分配。
  新测试交错直达／反射／完整／空更新，跨延时桶并交替单点、多点和零权重输入，
  检查旧频谱不残留、输出与完整响应逐位一致、未请求输出为正零。
- Release 精确／实时两档的普通及密集屏幕回放完整 manifest 均与基线逐位一致。
  实时档位的每个 worker 数及粒度候选都通过密集屏幕回放与固定／碎片分块比较。
- macOS Debug 房间 C++ 集成通过，Debug 房间库与 Release CLI 已重建；
  `cargo fmt`、dsp 全 targets 的 clippy（warnings denied）和 `git diff --check` 通过。
- Windows／Linux 验证后逐文件恢复原有源码；Windows Git 状态也恢复。未创建独立依赖缓存。

`room_bench` 新增 `--scenario all|static|pose|switch|ramps` 便于分开定位；
`room_stages` 新增移动源直达／完整响应准备时间。完整本地日志位于
忽略的 `local/room-v1/direct-workers-20261013/`。

随后尝试的宽 FFT 目标频谱直送原型未保留，理由及三平台数据见
