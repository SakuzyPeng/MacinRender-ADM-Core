# Rust ebur128 替换适配性评估

> 2026-10-04；基线 `20e9df8`。结论：**适合替换项目当前使用的 libebur128 接口**。
> 本文保留候选评估时的源码检查、独立探针及 macOS 测量。后续生产接入已完成，见 [Rust Meter 迁移](RUST_METER_MIGRATION.md)。

## 选型与范围

候选为 [sdroege/ebur128 0.1.10](https://docs.rs/ebur128/0.1.10/ebur128/)，MIT 许可，
Rust 1.60 起可用，本仓库 Rust 1.98.0 实测通过。它是 libebur128 的纯 Rust 移植，
使用正常 Rust API 时不需要 C 库。锁定版本并关闭额外 features，尤其不启用 `capi`、
`c-tests` 或 `precision-true-peak`。

实际依赖仅有 `bitflags 1.3.2`、`smallvec 1.16.2`、`dasp_frame 0.11.0`、
`dasp_sample 0.11.0`，均为 MIT / Apache-2.0 许可选择。`c-tests` 引入的 C 对照代码不在
上述依赖图中。评估程序直接链接项目既有 C 静态库，避免另外引入一个 C binding crate。

纯 Rust 不等于依赖内部完全没有 `unsafe`：其插值循环和部分架构的浮点环境控制仍使用
局部 `unsafe`。项目的普通算法层可以继续保持安全接口及 `forbid(unsafe_code)`，
由私有 FFI crate 承接 C 边界；该禁令本身不审计依赖内部实现。

当前 8 个直接使用 C 库的源文件中，所需能力均有对应接口：

| 当前用途 | Rust 能力 | 适配结果 |
|---|---|---|
| EAR / 双耳 / HOA / Apple / 通用扬声器离线计量 | `Mode::I \| Mode::TRUE_PEAK`，`add_frames_f32`、`loudness_global`、`true_peak` | 覆盖 |
| 实时 Monitor 的瞬时、短时、综合响度 | `Mode::S \| Mode::I`，三种 loudness 查询 | 覆盖；继续在 worker 执行 |
| 离线响度归一化 | `Mode::I` | 覆盖；静音及不足 400 ms 时的不可用结果保留 |
| 全局 True Peak 增益调整 | `Mode::TRUE_PEAK` | 覆盖；包含跨采样峰值 |
| HOA 7.1.4 声道权重、LFE 排除 | `set_channel_map` / `Channel` | 当前 12 个位置全部可表达；LFE 仍可单独测峰值 |
| seek 后重新开始积分 | `reset()` | 可原地清空状态；实测无分配且保留声道映射 |

调用位置是 `ear_renderer.cpp`、`binaural_renderer.cpp`、`hoa_renderer.cpp`、
`spatial_mixer_renderer.cpp`、`speaker_pcm.cpp`、`monitor_engine.cpp`、
`loudness_normalizer.cpp`、`peak_limiter.cpp`。测试中另有直接调用的响度 fixture。

## 数值和状态验证

使用 [独立评估工具](../../tests/tools/ebur128_eval/README.md) 将完全相同的 float32 样本
送入 Rust 和项目既有 C libebur128 1.2.6。Debug correctness 和 Release 数值检查均通过
49 组现用接口对照，以及另外的独立电平、分块、重置、输入参数和分配检查。

- 采样率：44.1、48、88.2、96、176.4、192 kHz。
- 声道数：1、2、4、5、6、8、12、16、24、64；含显式 HOA 7.1.4 映射。
- 信号：正弦、确定性混合噪声、静音、门限切换、脉冲和跨采样峰值。
- 边界：空输入、400 ms 与 3 s 前后、1/127/512/4096 帧分块、LFE-only、重置后重测。

Release 中的最大差异：

| 指标 | 最大差异 | 评估门限 |
|---|---:|---:|
| 综合 / 瞬时 / 短时响度 | `1.1291e-9 LU` | `0.001 LU` |
| True Peak | `2.9209e-6 dB` | `0.01 dB` |

独立构造的单声道 1 kHz、-20 dBFS 峰值信号测得 **-23.00360 LUFS**，符合预设
-23 ± 0.1 LUFS。跨采样峰值用例的样本峰值为 -3.92545 dBFS，测得 True Peak
-0.81163 dBTP，确认测量包含插值峰值。重置后与新建实例的响度结果逐位相同。

数值最大差异不包含 7 次极低电平残留差异：静音尾部 Rust 已归零时，C 仍可能返回
约 -665 LUFS。探针将**双方均低于 -300 LUFS**的差异单列，没有将它计为普通有效电平误差。
这远低于 -70 LUFS 绝对门限；综合响度仍受门限控制。瞬时/短时表头可能更早显示负无穷。

这些是本项目范围内的对照和独立信号检查。未下载、重跑完整 EBU 官方音频测试集，
不据此宣称新的 EBU 合规认证，也不承诺跨平台逐位相等。

## 实时处理与历史内存

模拟 600 秒立体声音频，以尽速方式喂入，每秒查询一次综合响度：

| 模式 | 准备完成后的 Rust 分配 | 综合响度查询平均耗时（Release） |
|---|---|---:|
| 默认完整历史 | 1 次扩容，请求新的 80,000 字节缓冲区 | 5.413 μs |
| `HISTOGRAM` | 0 次 | 1.162 μs |

默认历史队列先预留 5,000 个能量块，约 500 秒后需要增长。本轮扩容是从约 40 KB
到 80 KB，80,000 是新缓冲区请求大小，不是净增量。计数器只拦截 Rust 分配；这不是
C/Rust 的 RSS 比较，也不是实际音频设备运行 10 分钟的欠载测试。

另外，2/12/24/64 声道的已准备实例在 1 秒完整计量循环中均无分配；`reset()` 无分配。
短片段无分配不能推导为无限时长无分配。

接入建议：先保持完整历史模式及当前 worker 计量位置，保留现有数值语义。
`HISTOGRAM` 具有固定存储、固定规模查询，但引入能量分箱近似；本轮只验证它与 C 的
同模式对照，尚未建立它相对完整历史模式在全部内容上的误差约束，不应默认启用。

## 已复现的未用接口缺陷

**0.1.10 的 `set_max_history()` 在已有历史多于新上限时不能正确截断旧数据。**
本项目目前未使用该 API，因此不阻碍上表中的现用接口迁移。

复现：输入 12 秒正弦，缩短历史为 1,000 ms，再输入降低 20 dB 的 1.4 秒信号。

- Rust 报告的门控后能量块计数由 117 变为 120，超过 10 块上限。
- Rust 结果为 **-17.72660 LUFS**；C 参考结果为 **-37.67253 LUFS**。
- 源码原因位于 `src/history.rs` 的 `Queue::set_max_size()`：它没有在已有长度超过
  新上限时截断；后续 `add()` 仅在长度恰好等于上限时弹出旧块。

探针单独记录此失败，不将其隐藏在 49 组通过结果内。正式封装暂不暴露该 API；
若以后需要有限历史窗口，应先修复并补回归，不能将它直接当作限制内存的方案。

## Release 性能

本机 Apple M4 Pro / macOS arm64，Rust 1.98.0；C 参考来自项目现有 Release 静态库，
Ninja 确认为最新，编译参数含 `-O3 -DNDEBUG -arch arm64`。
每项处理 5 秒 48 kHz 合成 PCM，块大小 512，预热后五轮交替执行，取中位数。
创建、销毁和输入生成在计时外；包含处理及查询。Monitor 每 10 块查询 M/S、
每 100 块查询 I；离线模式在末尾读取 I 和各声道 True Peak。

| 模式 / 声道 | Rust | C | Rust / C 耗时比 |
|---|---:|---:|---:|
| 离线 I + TP，立体声 | 4.572 ms | 12.911 ms | 0.354 |
| 离线 I + TP，6 声道 | 11.317 ms | 38.096 ms | 0.297 |
| 离线 I + TP，显式 7.1.4 | 25.334 ms | 77.995 ms | 0.325 |
| Monitor S + I，立体声 | 10.511 ms | 16.527 ms | 0.636 |
| Monitor S + I，6 声道 | 25.371 ms | 42.032 ms | 0.604 |
| Monitor S + I，显式 7.1.4 | 56.393 ms | 97.610 ms | 0.578 |

这些是计量模块的微基准，不能换算成整个渲染器的加速比例。12/24 声道默认映射的
额外结果保留在原始记录中；该映射不会自动计入第 7 个及之后的声道，不宜把它当成
完整布局计量性能。上表 7.1.4 明确使用当前 HOA 的声道图。

## 正式接入边界

1. 在安全 Rust 层建立项目自有 `Meter`，只覆盖已用模式和显式声道图；不向公开 C ABI
   暴露 crate 类型。通过现有私有 `mradm-ffi` 提供有长度检查、所有权和 panic 保护的接口。
2. 参数错误需在项目层准确分类。crate 对非法采样率、声道数或缓冲长度有时使用 `NoMem`，
   不能直接把它翻译为项目的内存失败。
3. 保留静音/短音频的 optional 结果、LFE 的 LUFS 排除与峰值策略，以及异步任务完成后
   才销毁计量器的生命周期。固定格式下 seek 可使用 `reset()`。
4. C 和 Rust 的默认声道图都不是任意空间布局识别器。统一接口应将映射作为明确输入；
   既有普通多声道路径沿用默认图的问题需要单独的语义回归，不能当作换库自动修好。
5. 接入 8 处调用及 fixture 后，移除生产 `libebur128` 链接，更新许可证/SBOM，再做
   平台和端到端归一化、峰值调整及 ABI 验证。后续实施结果以迁移文档为准。
