# ROOM GPU 完整 Session：缩紧批次与异步晚场

日期：2026-10-18。基线 `6bd4937`，延续未提交的 `room-gpu-experiment` 原型。
本页记录第二个完整 Session 候选；[首版报告](ROOM_GPU_SESSION.md) 的失败记录继续保留。
默认 realtime 策略仍为 `room-realtime-v2`，exact 和公共 C ABI 不选择 GPU。

**结论：保留批次缩紧与异步晚场原型；两项短测零超时、数值通过，但首轮长测 1/22,500 超时，未达标。**
额外的单次传输和四组路径归约未证明稳定改善，均已撤回。三个候选的全部结果、源码／二进制哈希及
清理记录见 [validation.json](evidence/room-gpu-session-late/validation.json)。

## 本轮实现

CUDA Graph 增加 `(128 行响应, 64 次更新, 384 个卷积任务)` 和 `(320, 96, 384)` 的有界容量，
保留原有容量作为回退。选择依赖实际工作量；不依赖调用编号或基准场景，不裁掉响应或活动目标。

完整晚场 FIR 的前 2048 taps 仍由原 CPU 路径处理。其后的 2048 帧分区卷积移至独立 CUDA
stream，使用原准备阶段生成的 f32 频谱、相同 4096 点变换和完整分区历史。
原 `LongReader` 本来就在收齐一个 2048 帧输入块后生成未来输出，从下一 canonical block 起消费。
GPU 保留这一时序：异步生成结果，在下次使用前完成等待，再以原方向顺序提供给 CPU 头姿解码。
没有新增音频队列、改变 FIR 起点、尾长或输出延迟。

reset 保留待完成任务的所有权，完成后丢弃旧 epoch 的结果；第一次新提交清空设备历史。
新增本地用例特意在晚场结果尚待取回时 reset，并与原 Session 比较完整尾声。
准备与处理边界仍通过安全 Rust trait 隔离；CUDA DLL 只由研究示例加载。

## 诊断依据

先对首版算法构建独立诊断版本，使用 Rust 粗粒度计时和 CUDA Graph 外部事件。
512 次位置运动诊断为平均 4.008 ms、最大 6.010 ms、15 次超时；这些数字不作为性能验收。
在该事件序列中，每 256 帧实际有 96 或 288 行响应、48 或 80 次目标更新、332 个活动卷积任务，
原图却一律执行 512 行响应、128 次更新和 512 个任务的 FFT。

较慢调用还集中在晚场长分区到期的块。诊断中最慢一次 512 帧调用的晚场及解码阶段墙钟为
1.872 ms，GPU 完成等待为 0.613 ms。工作线程累计的内部阶段包含并行和嵌套，不能相加当作
关键路径；CUDA 事件区间也可能包含 GPU 调度等待，不能直接当作纯内核算术时间。
本候选组合实现了上述两项改动，没有将收益拆成未经隔离实测的百分比。

诊断实现是 `session_trace.h` 的编译宏 `ROOM_GPU_TRACE`，记录存入预分配缓冲，退出时输出；
正式二进制未定义此宏，也未启用 `room-profile`／`room-trace`。
事件捕获依据 [CUDA 12.0 Event Management](https://docs.nvidia.com/cuda/archive/12.0.0/cuda-runtime-api/group__CUDART__EVENT.html)。

## 数值与本地正确性

Windows 同机 CPU 与候选完整回放为 231,581 帧，包含尾声；固定／碎片输入在候选内逐位一致。
帧数、延迟、尾长、资源和控制配置一致；比较不搜索时移、不拟合增益、不裁剪输出。

- 最大相对 L2：`4.898492078127715e-7`，门槛 `2e-5`。
- 最大误差／参考峰值：`6.516114024176086e-7`，门槛 `2e-4`。
- 完整回放的运动、屏幕、headLocked、extent／diffuse、换房及分包检查通过，输出有限。

本地 48/96 kHz CPU 参考执行器对照覆盖新晚场调度、待取回结果时 reset、换房和尾声；
处理线程零分配检查通过。原有质量 9 项、零分配测试、clippy 和 C++ 格式／cppcheck 检查通过。
这些结果不代表 CUDA 驱动内部零分配、设备丢失恢复或 Windows GPU 的 48 kHz 已认证。

## 验收边界与复现

首个组合候选的第一轮位置长测为 22,500 次调用、平均 3.574801 ms、p99 4.5888 ms、
最大 5.3904 ms、**1 次超时**。因此该候选失败，其余五轮未执行。

随后形成第二个组合候选：把每块八次独立 H2D 拷贝合并为一块预分配 pinned slab 的单次拷贝，
并将每个响应桶的路径分成四个连续组，在 GPU 上独立计算后按固定组序相加。
分组只改变 realtime 的浮点归约顺序，不减少任何路径；没有原子浮点归约或完成顺序依赖。
该版本两项短测均为零超时，但位置／距离的均值为 3.735／3.753 ms，最大为 5.008／5.328 ms，
没有证明完整会话收益，距离场景余量约 6 微秒。因此没有进入该版数值扩展或长测，路径分组已撤回。
第三个候选只在首个组合候选上增加单次 H2D 传输。其位置／距离短测最大值为 4.7719／4.6719 ms，
均为零超时；同一份 231,581 帧数值复核通过，误差与首个组合候选相同。
但首次位置长测为平均 3.602372 ms、p99 4.5861 ms、最大 5.814 ms、**3/22,500 超时**，其余轮次停止。
没有将背景负载作为排除失败的理由，也不能从这些非交替配对的轮次断言单次传输导致退化。
它尚未证明稳定改善，因此该额外复杂度已撤回；当前源码与首个组合候选的已测运行时代码一致。
各版本数据独立保留，未拼接成功轮次或以较好的短测取代失败长测。
原型仍限本次 96 kHz 资源族和最多 32 源，尚无 macOS GPU 后端或公开 GPU 选档。
生产资源绑定、设备故障处理和完整 API 验证仍需后续工作。
