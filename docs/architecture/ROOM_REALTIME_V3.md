# ROOM realtime v3：浮点优化与子带研究

日期：2026-10-18。基线 `718a80495b812dcd442b8f5109dfd595afb1d1d5`。
**Windows 96 kHz／512 帧／32 源／8 workers 的零超时目标未达到。**
浮点优化的数值门槛与性能门槛分别报告；加载收益不代替运行时验收。
已完成项目与边界见下文；本轮不宣告原计划全部完成。完整统计见
[JSON](evidence/room-realtime-v3/validation.json)，子带研究见下文。

## 处置结论与后续门槛

按用户确认的 Windows 优先、短测失败即停止规则，本轮改动分为：

| 改动 | 处置 | 依据 |
|---|---|---|
| 有界时延准备并行、单次认证读取、距离集合弱缓存及缓存身份修正 | 可以独立采用 | Windows 加载明显加快，准备数据逐位检查与缓存正确性检查通过；单轮计时不承诺稳定幅度 |
| Windows 剖析、完整回放数值比较、加载／运行时计时及对应回归工具 | 保留 | 为后续 Windows 筛选提供必要证据 |
| realtime 融合查询、相位表、SIMD 卷积与 `room-realtime-v3` 晋级 | 当前组合不采用为生产交付方案 | 数值通过，但完整会话位置／距离短测各 1024/1024 次超时，且部分 16 源场景退化 |
| 平面布局、跨镜像批处理、活动目标批处理等失败组合 | 作废 | 没有稳定整体收益，已从生产路径移除 |
| 独立子带近似 | 仅保留研究 | Windows 早反射隔离链有收益；完整会话未验证，新增 40 ms 延迟和细频谱误差尚未完成声学验收 |
| 修正 AVX 顺序错误前的性能与长测记录 | 作废 | 来自数值错误的候选，不能参与性能或验收结论 |

已按采用结论拆分：生产路径撤回 realtime v3，实现归档到本地私有研究目录，策略恢复 v2。
加载与工具改动独立采用，见 [准备优化](ROOM_PREPARATION_OPTIMIZATION.md)。
原有用户研究改动保持原样。允许 realtime 放宽舍入的数值契约继续有效，但不代表本候选已获采用。

后续候选先在 Windows 完成必要的原生正确性检查，再以无插桩 Release 运行完整会话短测：
8 workers、96 kHz、512 帧、32 源，位置运动和距离运动各 1024 次调用。
任一调用超过 5.333333… ms 即停止该候选，不继续 macOS 性能矩阵或六轮长测。
只有新候选通过 Windows 短测才进入后续跨平台／长测验收；子带隔离链通过不能替代这个门槛。
加载改动按自身正确性和加载收益独立处理。

## 已测试的候选实现（运行时已撤回）

- 仅 realtime 走独立算术内核：每耳最多六个插值项，64-bin 分块融合 HRIR 插值、相位、路径乘法
  和响应桶累计；显式 FMA／SIMD，固定索引顺序。换房查询缓存、多点 extent／divergence、
  距离钳制及 DC／Nyquist 处理保留。
- realtime 分区卷积使用原生复数乘加。exact 的原表达式、FFT 入口、资源精度和归约顺序不变。
  没有全局 fast-math、FTZ、FIR 裁剪、路径删减、距离层删减或控制时钟改动。
- 原生路径整数相位表限制在 64 MiB 内，并与 HRIR bank 合计检查原有资源预算；大资源回退原有
  相位构造。它不保留第二份完整 HRIR／分区频谱。
- 时延估计使用独立、全进程最多四个线程的准备池。每任务独立 scratch，每行原 f64 算法不变；
  小输入串行，结果和错误按原行序收集。线程创建失败允许后续重试。
- 距离集合弱缓存隔离索引内容、处理采样率、展示名称、来源报告；命中仍逐层读取、核对长度和
  SHA-256。未命中只读取／认证一次，认证后的哈希复用于 SOFA 身份。缓存锁只保护查找和发布，
  不覆盖读取或计算；释放活动句柄后允许回收。没有磁盘缓存。
- 处理策略更新为 `room-realtime-v3`，公开 ABI、枚举及选档入口不变。

## 未保留的组合

测过逐 bin 动态项遍历、跨镜像频率块、32-path 引用展开、平面分区存储，以及共享输入的活动目标
批处理。它们没有稳定的整体收益。平面分区布局在 Windows 配对短测约慢 3%；活动目标批处理
在 Mac 也明显变慢，均已从生产代码移除。没有采用宽 FFT 频谱直送或缩短 FIR。连续分区的批量 FFT 尚未实现，不能列为已完成项。

最终融合路径筛选的均值（ms，96 kHz／512／32／8）：

| 分块 | Mac | Windows |
|---|---:|---:|
| 32 bins | 4.388 / 4.433 | 12.518 / 12.174 |
| 64 bins | 4.180 / 4.205 | 12.155（独立筛查） |
| 128 bins | 4.223 / 4.247 | 12.373 / 12.065 |

被测候选采用 64。Windows 三者差异很小；修正后的 64-bin 另有完整矩阵位置运动均值 12.102 ms。
三种分块均未通过 Windows 短测，不把这次筛选当作生产采用或统计上显著的分块优势证明。

## 数值和正确性

Mac Release 比较覆盖 48／96 kHz、单 SOFA／预处理 HRIR／九层距离集合，使用完整回放和尾声，
包含密集运动、方向接缝／近极点、屏幕映射、headLocked、diffuse、换房和固定／碎片分包。
六组 exact 的准备 manifest 与各 17 份 HRIR／分支／PCM 文件逐位相同；帧数、延迟、尾长相同。
realtime 最大相对 L2 为 `5.244e-7`，最大误差／参考峰值为 `8.623e-7`，均低于 `2e-5`／`2e-4`。
不进行时间搜索、增益拟合或裁剪。

另在 Release C++／C ABI 边界导出离线渲染、文件流式渲染和 Scene 流式渲染检查点，16 份 exact
PCM 与保存的变更前 Release 库逐位相同。96 kHz 公开 CLI／C ABI 集成测试覆盖文件 seek、Scene 分包和 epoch reset。

Mac 定向检查包括：62 项 DSP 测试、5 项缓存测试、room-trace 与零分配测试、C++ 房间／C header／
Python 验收工具 CTest、Release 96 kHz 集成。clippy（DSP／FFI 全 targets，warnings denied）、
Rust 格式检查、C/C++ changed gate、285 个函数／103 个结构体的私有 FFI 头检查通过。
C++ gate 仍输出既有“故意传入非法枚举值”的测试诊断；公开头没有修改。

Windows 原生测试发现并修复了 AVX `deinterleave_shfl` 的写回顺序错误；旧候选六轮长测及其性能值
全部作废，不用于验收。修正后的 48／96 kHz 完整距离集合回放通过：exact 的 manifest 和全部
17 份载荷逐位相同，realtime 最大相对 L2 `3.370e-7`、最大误差／参考峰值 `5.548e-7`。
原生单元、集成、缓存测试以及 canonical C++／C ABI 的 4 项 CTest 通过。

## 运行时与加载

独立无插桩 Release，复用 canonical 构建缓存，固定相同资源与事件。以下为 32 源完整矩阵单轮
各 1024 次调用的均值（ms）；p99、最大值、超时和峰值内存在 JSON 中。短测有波动，Windows 表中为 AVX 修正后的独立对照；
密集运动改善约 2–5%，仍全部超时，不能用较好的某一轮覆盖其它结果。

| 场景 | Mac 基线 → 候选 | Windows 基线 → 候选 |
|---|---:|---:|
| 静态 | 0.821 → 0.722 | 1.399 → 1.311 |
| 头姿 | 2.463 → 2.370 | 5.958 → 5.801 |
| 换房 | 2.724 → 2.629 | 6.782 → 6.682 |
| 位置运动 | 4.815 → 4.462 | 12.403 → 12.102 |
| 距离运动 | 4.490 → 4.418 | 11.629 → 11.073 |

Windows 修正后的分项剖析：每次调用的 worker 累计墙钟，响应生成 `47.01 ms`、HRIR 查询
`32.74 ms`、路径传递 `9.40 ms`、响应逆变换 `5.43 ms`、目标准备 `7.08 ms`、卷积 `15.94 ms`。
会话墙钟 `12.14 ms`，任务批次 `9.67 ms`。阶段嵌套且跨线程重叠，不能相加当作会话耗时。

Mac 公开 C ABI Scene 创建，三轮中位数（秒）：

| 采样率 | 无活动句柄准备：基线 → 候选 | 活动缓存命中：基线 → 候选 |
|---|---:|---:|
| 48 kHz | 8.155 → 5.367 | 7.901 → 0.764 |
| 96 kHz | 9.225 → 4.521 | 9.007 → 0.769 |

“冷”指没有存活的 prepared 句柄，保留 OS 文件缓存。命中仍认证全部层；测试计入会话分配。

Windows 私有 C 边界准备单轮（与 Mac 的公开 Scene 创建边界分别比较）：48 kHz 冷准备
`12.976 → 9.153 s`、活动命中 `12.449 → 0.390 s`；96 kHz 冷准备 `17.761 → 10.038 s`、
活动命中 `17.551 → 0.417 s`。单轮数字不作为稳定幅度承诺。

修正后的 32 源位置／距离运动短测均为 **1024 / 1024 次超时**，已足以否定本候选的零超时目标。
原计划的六轮／135,000 次长测已按用户要求停止，不再重复验证这个明确失败的候选。
修正后长测只完成一轮 1024 次基线，候选在首轮中途终止，未产生完整候选长轮统计；
不声称通过长测或空闲主机验收。初始错误候选的六轮不计入有效证据。

Windows 短矩阵没有采集独立峰值工作集，JSON 保留 null。中断前的 32 源候选观察峰值为
`1,393,156,096 bytes`，不能当作完整轮次的峰值。Mac 的完整进程峰值在矩阵 JSON 中。

Windows 的 997 项临时覆盖已逐项验证：恢复 703 个原文件，删除 294 个本任务创建的文件，
HEAD 与原始 Git 状态完全相同。临时任务目录和私人 SOFA 副本已删除，原有构建缓存保留。

## 独立子带研究

用户随后授权单独评估声学近似和新增延迟；该研究没有接入生产策略。
复核“评估 QMF 双耳处理方案 (2)”后，没有把常规双耳的加速比例直接套给 ROOM。已有共享 HOA
实验保留逐源多输出 FIR，密集运动收益很小；新原型直接在子带历史中处理镜像路径。

48 kHz 的 133-band 分数延时原型、96 kHz 的 261-band 分数延时原型，在 Mac 的早反射隔离链上
约快 3 倍。96 kHz 位置运动配对均值约 `1.611 → 0.545 ms`，距离运动约 `1.454 → 0.494 ms`。
静态则从约 `0.151 → 0.252 ms`，因为滤波器组增加固定成本。
Windows 对应的 96 kHz 早反射位置运动为 `4.844 → 1.169 ms`、距离运动为 `4.217 → 1.064 ms`；
静态 `0.218 → 0.471 ms`。这些同样只代表隔离链，不代表完整 ROOM。

八个静态位置的第三倍频程筛查：48 kHz 最大偏差约 `0.267 dB`、96 kHz 约 `0.309 dB`，
最大频带 ILD 差约 `0.266 / 0.260 dB`。细频谱误差的最坏位置 p95 约 `0.93 dB`，
窄陷波处最大仍约 `20 / 27 dB`（参考功率高于其每耳峰值 −60 dB 的频点）；不能用宽频带统计
掩盖这些差异。完整波形 L2 不作频率掩码。只补偿声明的固定延迟，保留完整前沿和尾声，没有拟合增益。
两个配置均增加约 **40 ms** 延迟；这不等同于传感器到耳机延迟，也不是可直接发布的结论。
尚缺完整 ROOM 集成、时变／换房声学检查和主观听感验收，不能据此宣布 Windows 完整会话零超时。

研究实现及复现方式已迁至独立子带工作区；位置及文件清单见 [本地工作区索引](../../local/room-experiments-workspaces-20261018/workspaces.json)。

## 复现与工作区

- 按项目 preset／Windows canonical MSVC/Ninja 配方构建；Rust 示例使用既有 Cargo target、
  `--release --locked --no-default-features`，不新建依赖缓存。正式计时关闭 profile／trace。
- `room_replay ROOM OUTPUT --hrir COLLECTION --quality exact|realtime --dense --screens --head-motion wrap`。
  exact 使用 `scripts/room/compare-replays.py`；realtime 使用 `scripts/room/compare-realtime.py`。
- `scripts/room/benchmark-windows.py --acceptance` 固定六轮矩阵；完整命令见
  [工具说明](../../scripts/room/README.md#windows-96-khz-零超时门槛)。
- 加载计时使用 `scripts/room/benchmark-prepare.py`，或 Release 私有边界示例
  `room_prepare_bench ROOM COLLECTION 3`。两种边界的数字不能直接混合比较。
- 本地完整原始日志、二进制、回放和试验源码在忽略目录 `local/room-realtime-v3-20261018/`。
  私人 SOFA 和主机路径不进入版本库。原有未提交研究代码保持原样。长测按用户要求停止，其余工作区已清理。
