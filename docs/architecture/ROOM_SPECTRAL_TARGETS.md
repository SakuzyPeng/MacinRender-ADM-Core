# 房间目标频谱直送原型：未保留

日期：2026-10-13。基线为 `e5803f6` 加上
[直达路径试验](ROOM_DIRECT_WORKERS.md)保留的优化。
本次试验不修改精确／实时档位的生产实现。三平台详细结果和代码／二进制哈希见
[JSON 记录](ROOM_SPECTRAL_TARGETS.json)。

## 尝试的实现

现有响应合成把各路径累加到 2048 点频谱桶，再 IFFT 成时域响应；短卷积将响应切成
256 帧分区，每个分区做 512 点 FFT。两处变换的长度和窗口不同，不能直接把桶频谱
当作现有卷积分区频谱。

本轮原型让短卷积直接消费已有的 2048 点桶频谱，跳过响应 IFFT、完整时域响应累加和
目标分区 FFT。处理步长保持 256 帧，输入使用更长的 overlap-save 历史，输出仍取每块
最后 256 帧；滤波器过渡复制现有的 10 ms 有限目标窗口，不改变测试事件的样本位置。

为避免循环卷积混叠，桶间距从 512 改为 256 帧。冻结资源的单路径核支持为 1359 taps，
因此满足 `1359 + 255 <= 2048 - 256 + 1`。路径、材质、HRIR 和 FIR 支持均未裁剪。
代价是每块输入／输出 FFT 都从 512 扩到 2048，目标频谱和历史占用也随之增加。

## 测量范围

这是**单声源短路径内核**试验，计时包含响应准备、目标提交和动态卷积；不包含 EQ、晚场、
并行 worker、完整 `Session`、解码或设备。不能把下面的微秒数当作 32 源端到端耗时。

三平台均使用 Rust 1.98.0 Release 和原生 FFT。每轮预热 32 块，测 6000 块，重复三轮，
第二轮交换基线／候选顺序。位置与头姿预先生成，分别测静态以及每 256／512／1024 帧更新。
两种分支组合为“仅直达”和“直达＋反射”。表中数值为每轮均值的中位数。

使用同一冻结资源字节；实际 HRIR 清单为 1850 个方向、480 个输入 taps、768 帧运行支持，
材质 FIR 为 512 taps，采样率 48 kHz。资源哈希见 JSON。

## 结果

直达和反射都每 512 帧更新时，每个 **256 帧处理块**的总耗时如下：

| 平台 | 原路径 μs | 频谱直送 μs | 总耗时变化 |
|---|---:|---:|---:|
| Mac M4 Pro | 116.05 | 120.70 | +4.0% |
| Windows i7-11800H | 185.45 | 192.19 | +3.6% |
| Linux Xeon | 602.88 | 616.33 | +2.2% |

准备阶段确实减少了工作，但卷积阶段增加的工作抵消了它。例如 Mac 的准备耗时由
105.16 降到 94.13 μs／块，卷积由 10.89 增到 26.67 μs／块。分阶段中位数独立计算，
不要求其和严格等于总耗时的中位数。

静态“直达＋反射”场景：

| 平台 | 原路径 μs | 频谱直送 μs | 新／旧耗时 |
|---|---:|---:|---:|
| Mac | 5.29 | 14.15 | 2.68 倍 |
| Windows | 8.10 | 18.74 | 2.31 倍 |
| Linux | 26.75 | 57.56 | 2.15 倍 |

仅直达、每 256 帧更新的极密集场景，Mac／Windows 总耗时分别下降约 5.0%／5.8%；
Linux 增加约 0.9%。这个局部收益不足以补偿其它场景的回退，不能作为实时档位的通用替代。

## 数值与实施决定

最大相对 L2：Mac `3.08e-7`，Windows／Linux `2.94e-7` 以内。
所有被测输出有限，包含静态和不断重定向时的有限目标过渡。它验证了这一卷积表示的
数值可行性，未验证任意碎片输入、seek、房间切换、完整 Session 截止时间或处理阶段零分配。

**不保留这个宽 FFT 消费器，也不接入生产会话。** 原因是测到的总体收益不足且静态退化明显。
这不排除其它分区频谱优化；若继续此方向，需要保留便宜的 512 点运行时卷积，并设计专门的
分区变换或其它复用方式，不能只省略不同长度之间的转换。

三平台原源码均已逐字节恢复，Windows 原 Git 状态也已恢复；上一轮未提交的直达优化保持原样。
原型、临时补丁、源码摘要和日志保存在忽略的 `local/room-v1/spectral-targets-20261013/`，
使用既有 Cargo target，没有创建独立依赖缓存。
