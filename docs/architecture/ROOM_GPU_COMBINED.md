# ROOM GPU 输入流水与有效分区 FFT 组合

日期：2026-10-18（本地时区）。基于 `6bd4937` 上已有的 GPU 实验，组合
[CPU 位置控制与输入流水](ROOM_GPU_PIPELINE.md) 和 [有效分区 FFT](ROOM_GPU_PACKED_TARGETS.md)。
两个单独候选的失败记录继续保留，本轮使用新组合重新执行短测、数值和全部六轮长测。

**固定 Windows 门槛通过：两项短测、完整数值检查和六轮 135,000 次长测均通过，长测零超时。**
最大调用为 **5.1795 ms**，小于 `512 / 96000` 秒，最小余量约 **0.153833 ms**。
随后补充的 **32 源换房出现 1/512 次超时，最大 5.6083 ms**。因此固定运动门槛通过，
全场景零超时尚未通过；停止扩展矩阵，没有用长测成功掩盖换房失败。
组合保留在显式 `room-gpu-experiment` 入口，默认 realtime、exact 和公共 C ABI 不选择它。
这不是生产音频设备欠载验收，也没有证明任意桌面负载下的硬实时保证。
[完整原始结果、校验值与清理证明](evidence/room-gpu-combined/validation.json) 和
[组合补丁](evidence/room-gpu-combined/candidate.patch) 随本页保存。

提交整理时仅从共享文件的提交快照中排除了未启用的 HOA 实验代码，原工作区研究内容保留。
独立快照通过 GPU 参考回放、质量、零分配、控制／worker 单测和 clippy，
见 [提交快照检查](evidence/room-gpu-combined/commit-checks.json)。历史性能数据仍严格对应冻结二进制及其原源码哈希。

## 组合内容

- 只有位置字段仍在插值、其他控制字段已稳定时，复用合并后的静态字段。位置继续使用原绝对
  样本位置的 f64 表达式，保留逐样本方向追踪、原点回退和屏幕映射。
- 稳定房间、没有 headLocked 信号或历史尾声、没有待切换房间且未开始 EOS 时，由调用线程
  准备下一块输入，同时八个 worker 渲染当前 256 帧块。输入和元数据先复制到 worker 拥有的
  缓冲，原 FIFO 消费位置不变。主 worker 任务在返回前收齐，原有异步晚场大分区时序不变。
  headLocked、换房和 EOS 继续沿用串行回退路径。
- 每个目标只打包完整有效 FIR 对应的 256 帧分区，逐耳执行原 512 点目标 FFT，再写回原
  物理槽。保留支持长度、末分区补零、响应桶顺序及全部距离层。该资源族预建 33 个 Graph
  容量组合，同一 stream 上的串行图共用相同规格的 FFT 计划和工作区。

没有新增音频排队延迟、准备线程或大型滤波器副本，没有截短 FIR。两项优化作用于不同阶段；
本轮只验收组合，不把单项历史轮次差异相加当作收益。

## 换房诊断

无插桩换房唯一超时为测量序号 `123`，含预热的调用序号 `155`，耗时 5.6083 ms。
此后仅做一次 512 调用的独立插桩诊断，使用 `room-trace` 和 `ROOM_GPU_TRACE`；正式二进制
和 DLL 始终冻结，校验值不变。诊断自身平均 3.057515 ms、最大 6.2874 ms、7 次超时，
不能替代或合并到正式验收结果。

诊断最慢 32 次均在过渡期：phase 1 有 6 次、phase 2 有 5 次、phase 3 有 21 次。
最慢一项在 phase 3，声源准备／提交阶段为 3.7388 ms，其中 GPU 提交为 1.4037 ms；
晚场与解码阶段为 0.9443 ms，最终 GPU 完成等待合计 0.0939 ms。
这些阶段有包含和并行关系，不能相加推导整次调用或归因于系统调度。
Windows 线程 CPU 计时在此尺度大量返回 0 或 15.625 ms，也不足以判断抢占。

当前过渡期会处理两套房间并回退到串行输入流程，下一步优先研究两套声源准备／提交的共享和批处理，
以及在不改变过渡语义的前提下扩大输入流水覆盖范围。该判断来自阶段墙钟；尚未证明某个具体
内核或后台进程导致无插桩的那一次尖峰。原始 [诊断记录](evidence/room-gpu-combined/diagnostic.json)
和 [GPU 事件记录](evidence/room-gpu-combined/diagnostic-gpu-trace.txt) 保留，没有进行新的占用排查。

## 数值和本地检查

Windows 同机 CPU realtime-v2 与 GPU 组合分别回放两种完整事件序列：默认回放覆盖 headLocked；
`--world-only` 回放验证可进入流水的世界坐标路径。两者均包括密集运动、头姿、屏幕、extent、
diffuse、换房、源移除和 EOS。每个回放的固定与碎片分包输出逐位一致，全部输出有限。

| 回放 | 输出帧数 | 最大相对 L2 | 最大误差／参考峰值 |
|---|---:|---:|---:|
| 默认，含 headLocked | 231581 | 4.898492078e-7 | 6.516114024e-7 |
| 纯世界坐标 | 231581 | 5.191120910e-7 | 6.468046673e-7 |

门槛分别为 `2e-5` 和 `2e-4`。比较完整 HRIR、分支响应及 PCM，不搜索时移、不拟合增益、不裁剪。
输入 96013 帧，EOS 后实际输出 135568 帧，延迟保持 256 帧。manifest 的 `tail_frames=135502`
是初始房间静态值，实际排尾终点来自换房后的 Session 状态。
两种 GPU 回放的完整 manifest 和所有检查点哈希也都与上轮输入流水候选相同；该结论限这些同资源回放。
通用数值比较器仍拒绝实验 manifest；本次驱动先严格核对 GPU 实验的四个标识字段，生成仅移除
该标识的临时比较 manifest，再使用原比较器，未放宽其他元数据或 exact 门槛。

macOS arm64 完成本地正确性检查：48／96 kHz 的 GPU 参考执行器回放、位置投影、worker 重叠及
错误／panic 后清理、零分配、原有质量检查均通过。有效分区 pack／install 的 CPU 模拟用实际
内核代码对照完整 FIR 时间域参考，覆盖零更新、边界支持长度、补零和保护区，UBSan／bounds
检查通过。clippy（warnings denied）、C++ 格式、cppcheck 和 GPU／HOA 特性共编译检查通过。
特性共编译不代表支持 GPU 与 HOA 混合使用。没有新增 macOS GPU 后端。

## 复现

按 [GPU 工具说明](../../scripts/research/room_gpu/README.md#完整-session-研究入口) 导出并认证
相同资源，使用既有 canonical 缓存构建，不启用 `room-profile`、`room-trace` 或 `ROOM_GPU_TRACE`。
CPU 数值参考使用相同 `room_replay`，省略三个 `--gpu-*` 参数；分别执行默认和 `--world-only`。

```powershell
$env:MR_ADM_ROOM_WORKERS = "8"
& $ROOM_REPLAY_EXE $ROOM96 $NEW_GPU_REPLAY --hrir $COLLECTION --quality realtime `
  --dense --screens --head-motion wrap --gpu-dll $GPU_DLL --gpu-fixture $PRIVATE_FIXTURE `
  --gpu-kernels $GPU_KERNELS
# 另一个独立输出目录追加 --world-only，再与同模式 CPU 参考比较。
& $ROOM_BENCH_EXE $ROOM96 1024 512 32 --hrir $COLLECTION --quality realtime `
  --scenario ramps --gpu-dll $GPU_DLL --gpu-fixture $PRIVATE_FIXTURE --gpu-kernels $GPU_KERNELS
# 零超时后，以 --scenario distance-ramps 执行另一项短测。
```

只有短测和完整数值通过，才按工具说明执行位置／距离各三轮、每轮 22500 次的长测；
任一超时即停止后续轮次。保留每次运行的二进制、源码和资源校验值及完整失败记录。

补充矩阵使用相同命令，将调用数改为 `512`，源数依次为 `1`、`16`、`32`，场景依次为
`static`、`pose`、`switch`。每项分别开启／关闭三个 GPU 参数，并交替两者的先后顺序。
若 GPU 超时则停止扩展；本轮最后的 CPU 32 源换房因此未运行。
诊断单独编译 DLL 时添加 `/DROOM_GPU_TRACE`，Cargo 添加 `room-trace`，复制到独立诊断文件名后
运行 `512 512 32 --scenario switch` 并在末尾追加 `--trace`，不得覆盖冻结的验收产物。

源码已包含本次组合，不要重复应用补丁。可在仓库根目录用以下命令核对源码与归档补丁一致：

```sh
git apply --reverse --check docs/architecture/evidence/room-gpu-combined/candidate.patch
```

该实验仍限本次 Windows CUDA／96 kHz 资源族和最多 32 源，尚未完成正式播放链路接入、
设备丢失恢复、GPU 驱动内部零分配或跨 GPU 型号验收。默认 exact／realtime 算术路径保持原样。

Windows 临时覆盖核对 356 项，恢复 87 个原文件、移除 269 个任务文件，原 HEAD 和 Git 状态一致。
本地与 Windows 临时私人资源已清理，本地删除前认证了 644,253,669 bytes 的 fixture 内容。
